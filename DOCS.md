## 1. Что это за система

Платформа для владельца бизнеса по продаже готовых фирм (ООО) на Avito. Одно Next.js-приложение, одна база — **три рабочих поверхности**:

| Компонент | Кто пользуется | Точка входа |
|---|---|---|
| **Telegram-бот** | владелец и партнёры — смотрят базу, добавляют компании | `lib/telegram/bot.ts` |
| **Avito-бот** | клиенты с площадки — автоответчик по модели «2 сообщения» | `lib/dialog/process.ts` |
| **Админка** | владелец — импорт, редактирование, экспорт, лиды | `app/admin/*` |

Все три работают с **одной базой** (таблица `companies` и связанные). Avito-бот пишет карточки продавцов и лиды; Telegram-бот читает базу и добавляет карточки; админка — интерфейс ко всему этому.

### Стек

- **Next.js 16.2** (App Router, Turbopack, Node runtime) на **Vercel**
- **Neon PostgreSQL** через `@neondatabase/serverless` (HTTP-драйвер, не TCP)
- **OpenRouter** — LLM (по умолчанию `google/gemini-2.5-flash`)
- **DaData** — данные ЕГРЮЛ по ИНН
- **Telegram Bot API** — рабочий бот и алерты
- **SheetJS (`xlsx`)** — импорт и экспорт Excel
- **Vitest** — тесты (135 штук)

## 3. Модель данных

Полная схема — `lib/db/schema.sql`. Ключевой принцип: **raw + normalized**. Исходное значение из Excel никогда не теряется (`*_raw`), рядом кладётся нормализованное; что не распарсилось — помечается `needs_review` и правится вручную.

### `companies` — центральная таблица

Группы полей:

- **Идентификация:** `id`, `name`, `inn` (только цифры), `inn_raw` (как в файле: `O600010917`, «По запросу»)
- **Закрытые данные:** `seller_contact` — контакт продавца, **никогда не уходит клиенту** (INV-4)
- **Нормализованные:** `region_code`, `year_reg`, `tax_system`, `turnover_last_m`, `price_k`, `buy_price_k`, `has_license`
- **Сырые:** `city_raw`, `year_raw`, `turnover_note`, `price_raw`, `tax_raw`, `extra`
- **Обороты по годам:** `turnovers` jsonb — `{"2023": 92, "2024": 82.2}`
- **ЕГРЮЛ (DaData):** `egrul_status`, `egrul_name`, `egrul_reg_date`, `egrul_address`, `egrul_okved`, `egrul_data`, `egrul_checked_at`
- **Служебные:** `status`, `source`, `needs_review`, `review_notes`, `dialog_id`

#### Статусы (`status`) — важнее всего понимать

| Статус | Смысл | Видит клиент/гость | Видит админ в боте |
|---|---|---|---|
| `draft` | черновик, требует проверки | ❌ | ✅ (с пометкой «ЧЕРНОВИК») |
| `verified` | в продаже, витрина | ✅ | ✅ |
| `reserved` | забронирована | ❌ | ❌ |
| `sold` | продана | ❌ | ❌ |
| `archived` | архив (замена удалению) | ❌ | ❌ |

**Всё, что создаётся автоматически, попадает в `draft`** — и импорт, и оба бота. В продажу карточку переводит человек. Это самая частая причина вопроса «почему бот показывает мало компаний»: остальные лежат в черновиках.

**Перевод в `verified` снимает `needs_review`** — во всех путях: форма карточки, массовая смена статуса, кнопка «Сразу в продажу» в боте. Смысл простой: раз владелец выставил карточку в продажу, значит он её подтвердил.

Физического удаления карточек нет — «удаление» это перевод в `archived`.

#### Источники (`source`)

`import` (Excel) · `avito_bot` (карточка продавца из диалога) · `manual` (руками или «Из сообщения») · `quick` (быстрое добавление по ИНН) · `telegram` (разбор переписки в Telegram-боте).

### Остальные таблицы

- `imports` + `import_rows` — двухфазный импорт: staging → предпросмотр → применение
- `company_audit` — история правок: `{поле: {old, new}}`, `actor` = `admin` / `bot` / `import:<id>` / `tg:<chat_id>` / `admin:paste`
- `offers` — зафиксированные выдачи клиентам: короткий код (`K7M`) + состав в порядке позиций. Нужно, когда клиент пишет «интересует позиция 3»
- `tg_users` — пользователи Telegram-бота и роли
- `dialogs`, `processed_messages`, `bot_actions`, `leads`, `blacklist` — рабочие таблицы Avito-бота

## 4. Telegram-бот

Главный рабочий инструмент владельца. Код: `lib/telegram/bot.ts` (роутер), `api.ts` (вызовы Telegram), `users.ts` (роли), `parse-short.ts` (разбор краткого ввода).

Вебхук: `POST /api/telegram/webhook`, защищён заголовком `X-Telegram-Bot-Api-Secret-Token` (`TELEGRAM_WEBHOOK_SECRET`). Отвечает 200 сразу, обработка — в `waitUntil`. Регистрация: `npx tsx scripts/register-tg-webhook.ts`.

### Роли (`tg_users.role`)

| Роль | Права |
|---|---|
| `admin` | вся база + черновики, добавление компаний, выдача доступа. Назначается автоматически, если `chat_id` есть в `TELEGRAM_ADMIN_IDS` |
| `partner` | полные карточки компаний в продаже |
| `guest` | зависит от `TELEGRAM_GUEST_ACCESS` |
| `blocked` | бот молчит |

`TELEGRAM_GUEST_ACCESS`: `full` — полные карточки всем; `anonymous` (по умолчанию) — обезличенный список; `closed` — только просьба запросить доступ + алерт админам.

### Кнопки и команды

Клавиатура гостя: `📋 Все компании`, `🗺 Регионы`, `📥 Скачать таблицу`, `✍️ Написать менеджеру`.
Клавиатура админа — вместо контакта менеджера: `➕ Добавить`, `👥 Пользователи`.

**Связь с менеджером:** кнопка «✍️ Написать менеджеру» (команды `/manager`, `/contact`) даёт прямую ссылку на личку владельца — логин из `TELEGRAM_ADMIN_USERNAME`, по умолчанию `@bizgarant`. Одновременно владельцу приходит уведомление, кто именно хочет связаться. Тот же контакт подставляется в карточку варианта и в ответ «не понял запрос».

Команды админа: `/inn <ИНН…>`, `/add <текст>`, `/regions`, `/users`, `/grant <chat_id>`, `/revoke <chat_id>`.

### Порядок веток роутера (`handleUpdate`) — менять осторожно

1. `callback_query` → `more:` (страница списка), `grant:`, `verify:` (последние два только для админа)
2. `/start`, `/help`, «помощь»
3. Админские команды: `/users`, `/grant`, `/revoke`, `/inn`, `/add`, `➕`
4. `📋 Все компании` → список
5. `🗺 Регионы` / `/regions` → сводка по регионам
6. **ИНН от админа** — 10 или 12 цифр → быстрое добавление через ЕГРЮЛ
7. **Номер карточки** — `^[№#]?\s*(\d{1,9})$` → одна карточка
8. **Регион** — свободный текст через `regionFromText`
9. **Админ + текст > 60 символов** → разбор переписки нейросетью
10. Иначе — «Не понял запрос» + алерт админам

Порядок важен: ИНН (10–12 цифр) проверяется **до** номера карточки (до 9 цифр), поэтому они не конфликтуют.

### Список компаний и пагинация

`sendCompanyList(chatId, role, regionCode, offset)`:

- Запрос берёт `LIMIT 11` — одиннадцатая запись означает, что есть продолжение (`hasMore`)
- **Порядок — сначала недавно добавленные** (`created_at desc, id desc`): продавать нужно свежие карточки
- Админу выдаются статусы `verified` + `draft`, остальным — только `verified`
- Заголовок всегда содержит диапазон и общее число: «Компании, 1–10 из 34»
- Если есть продолжение — кнопка «➡️ Показать ещё» с `callback_data` вида `more:<offset>:<регион|пусто>` (лимит Telegram — 64 байта). Админу она идёт под последней карточкой, остальным — под итоговой строкой
- Черновики помечаются «⚠️ ЧЕРНОВИК (клиентам не виден)»

**Что видит кто** (`lib/format/company-card.ts`):

| Роль | Функция | Поля |
|---|---|---|
| админ | `formatCompanyCard({showBuyPrice:true})` | всё, включая цену закупа |
| партнёр, гость | `formatPartnerCard` | название, ИНН, год создания, налоговый режим, адрес, расчётный счёт, обороты по годам, цена продажи, номер в базе |

Партнёру и гостю **не показываются**: контакт продавца, цена закупа, ЗСКА и «дополнительно» (там бывают долги и причина продажи).

### Выгрузка таблицы в чат

Кнопка «📥 Скачать таблицу» (или `/export`) присылает файл `.xlsx` прямо в Telegram — тот же формат, что и экспорт из админки:

| Роль | Что попадает в файл |
|---|---|
| админ | вся база, режим `full` — со всеми полями, включая контакт продавца и цену закупа |
| партнёр, гость | только `verified`, режим `nocontacts` — та же полная таблица без контакта продавца и цены закупа |

Файл отправляется через `sendDocument` (multipart, `lib/telegram/api.ts`). О каждой выгрузке не-админом владельцу приходит уведомление.

### Добавление компаний (только админ)

- **По ИНН** — прислать ИНН, можно с телефоном и ценами: `7328108216 тел 89278250111 закуп 20 цена 100 альфа`. Название, год, регион, адрес, ОКВЭД тянутся из ЕГРЮЛ через DaData. Налоговый режим DaData не отдаёт → карточка помечается `needs_review`. Под ответом — кнопка «✅ Сразу в продажу»
- **Из переписки** — `/add` + скопированный диалог. Текст обезличивается (телефоны, email, ссылки, ИНН → плейсхолдеры), уходит в LLM, возвращается структура, реальные значения подставляются обратно уже у нас

### Поиск по регионам

`regionFromText` (`lib/normalize/regions.ts`) понимает:
1. точное совпадение с синонимом (`рт`, `челны`, `казань`)
2. точное совпадение с названием из `REGION_NAMES` («Татарстан», «Москва и МО»)
3. вхождение в фразу, со склонениями («в казани», «есть что-то в Татарстане?») — сравнение по основе слова
4. короткие синонимы (`рт`, `нн`, `но`) — только как отдельное слово, иначе «Новосибирск» ловился бы на «но»

Справочники: `REGION_SYNONYMS` (город/сокращение → код), `REGION_NAMES` (код → название), `KLADR_TO_REGION` (код региона ЕГРЮЛ → наш код). Казань выделена отдельным кодом `kzn`, остальной Татарстан — `rt`.

## 5. Avito-бот

Автоответчик в мессенджере Avito. Экономика жёсткая: Avito берёт от 490 ₽ за **целевой чат**, а чат становится целевым при обмене контактами, отправке ссылки или 5+ сообщениях. Отсюда инварианты.

### Инварианты (нарушение = провал приёмки)

- **INV-1** — не больше 2 исходящих сообщений на диалог. Жёсткий счётчик в `sendBotMessage`, `dialogs.bot_messages_sent`
- **INV-2** — никаких ссылок, телефонов, адресов, конкретных цен. `violatesInv2()` проверяет **каждое** сообщение перед отправкой; нарушение → сообщение не уходит, владельцу летит алерт
- **INV-3** — не хватило данных → третье сообщение не досылается, диалог закрывается эскалацией или отказом
- **INV-4** — клиенту с площадки никогда не раскрываются ИНН, название и контакты продавца. Подбор — только обезличенные карточки (`formatOffers`, белый список полей). Это касается **Avito-бота**; в Telegram-боте владелец сам решает, что показывать партнёрам (`formatPartnerCard`), и там название с ценой открыты, а ИНН и контакт продавца — нет

Все тексты клиенту — **шаблоны в коде** (`TEMPLATES` в `lib/dialog/state.ts`), не генерация LLM. Это и есть гарантия INV-2/INV-4: LLM только анализирует, решения принимает код.

### Guards (`lib/avito/guards.ts`), по порядку

1. невалидный payload → игнор
2. своё сообщение (`author_id == user_id`) → игнор (защита от петли)
3. **объявление не из белого списка `AVITO_ITEM_IDS`** → игнор до любых реакций
4. `system` → игнор; `link` / `location` / `image` / `voice` → эскалация
5. `chat_type != u2i` → игнор
6. пустой текст → игнор

Дальше в `processMessage`: чёрный список по `author_id`, идемпотентность по `processed_messages.avito_message_id`.

### Машина состояний

```
new ──достаточно данных──> finalize (карточка продавца / подбор покупателю) → escalated
 │
 └──мало данных──> вопросы (1 сообщение) → awaiting_reply
                                              │
                    ├─ данных хватило → finalize → escalated
                    ├─ не хватило     → escalated (INV-3, третьего вопроса нет)
                    └─ непонятно      → rejected
```

Триггеры немедленной эскалации от LLM: `asks_human`, `legal_scheme`, `price_talk`, `asks_contacts`, `uncertain_parse`. Любая ошибка LLM → `uncertain_parse` → эскалация (безопаснее молчаливого падения).

Диалоги в терминальных статусах (`escalated`, `rejected`, `closed`) продолжают писать входящие в `bot_actions`, но бот молчит — это нужно для исходящих кампаний.

Вебхук: `POST /api/avito/webhook/<AVITO_WEBHOOK_SECRET>`, секрет в пути, ранний 200, обработка в `waitUntil`.

### Клиент Avito (`lib/avito/client.ts`)

OAuth2 client_credentials с кэшем токена. Обработка ошибок: `401` → обновить токен и повторить; `402` → алерт «проверьте подписку и аванс»; `403` → алерт «уровень подписки / тип ключа»; `429` → backoff; `5xx` → 2 повтора.

Требования доступа: Messenger API работает только на подписке «Расширенный»/«Максимальный», ключ — от аккаунта **компании**, не сотрудника.

## 6. Админка

Basic Auth на `/admin` и `/api/admin` через `proxy.ts` (в Next.js 16 middleware называется так; файла `middleware.ts` в проекте нет). Если `ADMIN_USER`/`ADMIN_PASSWORD` не заданы — 503, доступ закрыт (fail closed).

| Страница | Что делает |
|---|---|
| `/admin` | дашборд: счётчики, компании по статусам, последние эскалации |
| `/admin/companies` | таблица с фильтрами, массовая смена статуса и удаление, экспорт, проверка ЕГРЮЛ |
| `/admin/companies/[id]` | карточка: редактирование, обороты по годам, аудит, проверка ЕГРЮЛ |
| `/admin/companies/new` | добавление: быстро по ИНН или полная форма |
| `/admin/paste` | вставить переписку → LLM разберёт → предпросмотр → сохранить |
| `/admin/imports` | импорт Excel: загрузка → diff → применить/отменить |
| `/admin/offers` | история выдач клиентам по коду списка |
| `/admin/leads` | лиды из Avito-бота, отметка «обработан» |
| `/admin/dialogs` | диалоги и история сообщений |
| `/admin/help` | инструкция для владельца |

Фильтры таблицы: поиск (ID / название / ИНН), регион, статус, налог, источник, диапазоны оборотов и цены, «требует проверки». Те же фильтры уходят в экспорт.

### Проверка статусов по ЕГРЮЛ

Кнопка «🔍 Проверить статус компаний» на странице списка прогоняет через DaData все карточки с ИНН (кроме архивных), начиная с самых давно проверенных, и показывает окно с итогом: сколько проверено, у кого статус изменился, кто больше не действует. Недействующие можно тут же убрать — в архив или удалить из базы.

За один прогон обрабатывается не больше `SWEEP_LIMIT` = 150 карточек (лимит времени функции); остаток показывается в окне и проверяется следующим запуском.

### Удаление карточек

Два разных действия:

- **Архив** — карточка остаётся в базе и в истории, но исчезает из выдачи. Обычный способ убрать из продажи
- **Удаление** — безвозвратно стирает карточку. Аудит уходит каскадом, ссылки в лидах обнуляются, история импорта (`import_rows`) сохраняется. Доступно на карточке и массово по чекбоксам

### Экспорт

Кнопка «Экспорт .xlsx» спрашивает наполнение:

- **с контактами и ценой** — все поля карточки, включая контакт продавца и цену закупа (только для внутреннего использования);
- **без контактов и цен закупа** — та же полная таблица, но эти две колонки не попадают в файл; такой файл можно отдать партнёру.

Режим передаётся параметром `?mode=full|nocontacts`. Обороты разворачиваются в колонки по годам, состав колонок вычисляется по всей выборке. Порядок строк — сначала недавно добавленные. Тот же выбор доступен для `.csv`.

Состав и порядок столбцов (`toExportRow` в `lib/export/xlsx.ts`) — по важности при работе с таблицей:

1. **Главное:** ID, Название, ИНН, *[Телефон продавца — только `full`]*
2. **Основное:** Регион, Год создания, Система налогообложения, Расчётный счёт (банки), по столбцу на каждый год оборотов, Цена продажи, *[Цена закупа — только `full`]*
3. **Прочее:** ЗСКА
4. **Второстепенное, в конце:** ОКВЭД, Адрес — длинные тексты, мешают читать таблицу

Ширина колонок задаётся через `!cols` (карта `COLUMN_WIDTH`), чтобы название, ИНН и телефон были видны без ручной подгонки.

В выгрузку **не входят**: Сотрудники, Лицензия, служебные Статус, Источник, Требует проверки, Статус ЕГРЮЛ, Проверено ЕГРЮЛ, Добавлена — и «Дополнительно». В последнем лежит сырой текст продавца, из которого уже разобраны обороты и банки; в базе и карточке админки поле остаётся, в файл не попадает.

Массовые операции: по отмеченным чекбоксам или **по всему текущему фильтру** (кнопка «Применить ко всем N»). Каждая правка пишется в `company_audit`.

## 7. Импорт Excel

Двухфазный, код в `lib/import/{parse,match,apply}.ts`.

1. **Parse** — читает первый лист, ищет колонки по вхождению подстроки (регистронезависимо): «название», «инн», «продавец», «оборот», «закуп», «цена», «налог», «город», «год», «дополнит» + хвостовые `Unnamed:*`. Обязательны «название» и «инн»
2. **Match** — по нормализованному ИНН → `update`; по `lower(trim(name))` → `update` с пометкой; иначе `insert`. Карточка, созданная Avito-ботом (`source='avito_bot'` + `dialog_id`), → `conflict`, автоматом не перезаписывается
3. **Apply** — транзакцией, каждая правка в `company_audit` с `actor='import:<id>'`

**Правило «import never blanks»:** пустая ячейка Excel никогда не затирает существующее значение. Обновляются только непустые новые значения; `has_license` можно только включить. Покрыто тестами `lib/import/__tests__/match.test.ts`.

## 8. Нормализация (`lib/normalize/`)

Общие правила для импорта **и** ботов — один и тот же код, чтобы данные не расходились.

| Модуль | Что делает |
|---|---|
| `inn.ts` | цифры, замена латиницы `O→0`; валидны 10 и 12 знаков |
| `year.ts` | `08.24`, `15.03.23г`, `2021-09-27` → год |
| `region.ts` + `regions.ts` | город/синоним → `region_code`, справочники, `regionFromText` |
| `price.ts` | цены в **тысячах** ₽; «Дог» → null |
| `tax.ts` | `осно` / `усн 6` / `усн д-р` / `аусн` → enum |
| `turnover.ts` | `23-4млн; 24-12млн` → `{2023:4, 2024:12}` + последний оборот. Годы двух- и четырёхзначные, единицы млрд/млн/тыс приводятся к млн. `extractTurnovers` дополнительно отдаёт текст без разобранных оборотов — чтобы они не дублировались в «дополнительно» |
| `extra.ts` | банки (≈45 названий, с падежами и аббревиатурами), признак лицензии |

Что не распарсилось — в `problems[]` → `needs_review` + `review_notes`.

Отдельная тонкость: `lastFullYearTurnover` берёт последний **завершённый** год. Текущий год неполный и занижал бы картину (фирма с 33 млн за 2024 выглядела бы как 0,5 млн за 2026).

## 9. LLM и приватность

Два вызова OpenRouter:

- `lib/llm/openrouter.ts` — анализ диалога Avito (`intent`, `extracted`, `escalate_reason`, `has_enough`)
- `lib/llm/parse-company.ts` — разбор произвольного текста в карточки компаний

**Обезличивание обязательно** (`lib/llm/anonymize.ts`): телефоны, email, ссылки, `@handle` и ИНН заменяются плейсхолдерами `[PHONE_1]`, `[INN_1]` **до** отправки. Обратная подстановка — только на нашей стороне после ответа. Данные ЕГРЮЛ в LLM не передаются вообще.

Ответ всегда парсится в строгий JSON; при любой ошибке — безопасный fallback с эскалацией.

## 11. Безопасность

Проведён отдельный аудит; текущее состояние:

- **SQL-инъекции невозможны** — весь пользовательский ввод идёт через параметризованные запросы (tagged templates neon и `$n`). Динамические имена колонок берутся из белых списков `EDITABLE_TEXT` / `EDITABLE_NUM`
- **Ключ OpenRouter недостижим через бота** — гость не может инициировать LLM-вызов: `/add` и разбор длинного текста доступны только админу
- **Prompt-инъекция ограничена дизайном** — ответ LLM никогда не уходит клиенту напрямую, только шаблоны + данные из БД, под фильтром INV-2
- **Вебхуки fail-closed** — 404, если секрет не задан или не совпал. Админка — 503, если не настроены креды
- **Алерты владельцу шлются без `parse_mode`** — иначе текст клиента с символами `<`, `>`, `&` ломал разметку, Telegram отклонял сообщение и уведомление об эскалации молча пропадало

Остаточные мелочи (низкий риск): сравнение пароля в `proxy.ts` не constant-time; у `notifyAdmins` в Telegram-боте нет дедупликации (гость может спамить алертами).

## 13. Эксплуатация и подводные камни

**Деплой.** Push в `master` на GitHub → Vercel собирает сам. Сборка занимает ~15 секунд.

**Локальный `npm run build` требует интернета** к `fonts.googleapis.com` (`next/font` тянет Geist). Без доступа сборка падает — на Vercel всё в порядке, это не баг кода.

**Нестабильная сеть на машине владельца.** Через VPN-туннель доступность хостов плавает: `api.vercel.com`, `registry.npmjs.org` и Neon периодически недоступны из Node (`UND_ERR_CONNECT_TIMEOUT`), при том что браузер работает. Если `vercel --prod` или скрипты к БД падают с таймаутом — это сеть, а не код; деплой в таком случае идёт через `git push`.

**«Бот показывает мало компаний».** Почти всегда это статусы: клиентам видны только `verified`. Проверить можно кнопкой «🗺 Регионы» — админу там выводится «Всего в базе: N (в продаже V, черновиков D, архив A)», или в заголовке списка «1–10 из N». Массовый перевод черновиков в продажу — в админке, блок «Применить ко всем N».

**Номера в боте — это ID карточек**, а не порядковые номера. Сортировка по `id`, поэтому первыми идут самые старые записи. По этому же номеру клиент говорит «интересует № 223», и владелец открывает `/admin/companies/223`.

**Регистрация вебхуков** после смены домена: `scripts/register-webhook.ts` (Avito), `scripts/register-tg-webhook.ts` (Telegram).

**Полезные скрипты** (`scripts/`, запуск `npx tsx --env-file=.env.local scripts/<имя>`): `check-webhook.ts`, `check-tariff.ts`, `check-egrul-all.ts`, `apply-egrul.ts`, `preview-cards.ts`, `set-tg-role.ts`, `test-quick-add.ts`.

`backfill-turnovers.ts` — дозаполнение существующих карточек: раскладывает обороты по годам из текста и приводит банки к каноническим названиям. Ничего не затирает (обороты доливаются, банки пишутся только поверх распознанных), каждое изменение уходит в `company_audit` с actor `backfill`. Сначала запускать с `--dry` — покажет, что изменится, без записи.

## 14. Что стоит помнить при доработках

- **Не отправлять клиенту ничего, кроме шаблонов** — любой новый текст в Avito-бот проводить через `violatesInv2`
- **Не расширять белый список полей** в выдаче клиенту без явного решения — это INV-4
- **Порядок веток в `handleUpdate`** значим (ИНН vs номер карточки)
- **`callback_data` ограничена 64 байтами** — не класть туда фильтры целиком
- **Новые значения `source`** добавлять сразу в `SOURCES` (`app/admin/companies/page.tsx`) и `SOURCE_RU` (`lib/export/xlsx.ts`), иначе карточки нельзя будет отфильтровать
- **Автоматика создаёт только `draft`** — не менять на `verified` без явной просьбы владельца
- **Любая правка карточки** должна писаться в `company_audit`
